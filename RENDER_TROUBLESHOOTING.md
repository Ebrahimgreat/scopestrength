# Render Database Connection Fix

## Error: "The database does not exist" / "connection not available"

This happens when your web service can't connect to PostgreSQL during migration.

---

## Solution: Check These 3 Things

### 1️⃣ Verify Database Exists and is Running

**Go to Render Dashboard:**
1. Look for a PostgreSQL service named `crohnjobs-db` (or similar)
2. Check its status - should show **"Available"** (green)
3. If it doesn't exist, create it:
   - Click **"New +"** → **"PostgreSQL"**
   - Name: `crohnjobs-db`
   - Database: `crohnjobs`
   - Region: **SAME as your web service!**
   - Plan: **Free**
   - Click **"Create Database"**
   - Wait 2-3 minutes

---

### 2️⃣ Fix DATABASE_URL (Most Common Issue!)

**The problem:** You might be using the EXTERNAL database URL instead of INTERNAL.

**In your database (`crohnjobs-db`):**
1. Go to **Info** tab
2. You'll see TWO URLs:
   - ❌ **External Database URL** - starts with `postgres://...render.com`
   - ✅ **Internal Database URL** - contains `dpg-...` and `.internal`

**Copy the INTERNAL DATABASE URL** (the one with `.internal` in it)

**In your web service (`crohnjobs-web`):**
1. Go to **Environment** tab
2. Find `DATABASE_URL`
3. **Replace it with the INTERNAL URL you just copied**
4. Click **"Save Changes"**

**Example of correct INTERNAL URL format:**
```
postgres://crohnjobs_db_user:PASSWORD@dpg-XXXXX-internal/crohnjobs_db
```

---

### 3️⃣ Verify Same Region

**Check that both services are in the SAME region:**
1. Database → **Info** → Region
2. Web Service → **Settings** → Region
3. If different, you'll need to recreate one (preferably the database)

---

## Quick Fix Steps

### If You Used Manual Setup (Option A):

1. **Check if DATABASE_URL is set:**
   - Web Service → **Environment** → Look for `DATABASE_URL`
   - If missing, add it with the INTERNAL URL from your database

2. **Redeploy:**
   - Web Service → **Manual Deploy** → **Deploy latest commit**

### If You Used Blueprint (Option B):

The database should link automatically, but if it failed:

1. **Delete both services**
2. **Make sure `render.yaml` is committed and pushed**
3. **Try Blueprint again** - it should create both at once
4. **OR switch to Manual Setup (Option A)**

---

## After Fixing DATABASE_URL

Once you've updated the DATABASE_URL with the INTERNAL connection string:

1. Go to your web service
2. Click **"Manual Deploy"** → **"Deploy latest commit"**
3. Watch the logs for:
   ```
   ==> Running preDeploy command
   [info] Migrations already up
   ==> Your app is live
   ```

## Still Getting Errors?

### Error: "SSL connection required"

**Fix:** Update `config/runtime.exs`:

Find this line (~line 51):
```elixir
config :crohnjobs, Crohnjobs.Repo,
  # ssl: true,
```

Change to:
```elixir
config :crohnjobs, Crohnjobs.Repo,
  ssl: true,
  ssl_opts: [verify: :verify_none],
```

### Error: "connection timeout"

**Check:**
1. Database is "Available" (not "Suspended")
2. Both services in same region
3. Using INTERNAL database URL

### Error: "too many connections"

**Fix:** Lower pool size in environment variables:
- Add/Update: `POOL_SIZE=2` (default is 10, too high for free tier)
